# Checkpoint, quantization and install signatures

Scope: the report is stopped by an **artifact** rather than by a phase — a quantization method the build does not know or a checkpoint whose weight/aux-tensor keys do not match it, a pip resolution that cannot exist, an image tag/arch that disagrees with the box, an install or build step that fails, a dependency pin two project files state differently, or a version string that disagrees with the checkout. The engine may not even start (track D: install/document), or it starts and refuses the checkpoint at load (track B); the row names the owner. The phase-shaped siblings — engine never ready, load/capture stalls, arg and platform gates — are in `startup-and-load.md`.

Inherit `index.md` and the SKILL.md rules. Rows are in no particular order — scan the left column, and read the middle cell before following the link.
