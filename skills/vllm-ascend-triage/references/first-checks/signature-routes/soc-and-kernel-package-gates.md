# SoC, device-type and kernel-package signatures

Scope: the paste is decided by **which chip, which build stamp or which op store** the
engine met, not by a phase of the launch — 310P (`Atlas 300I Duo`) against A2/A3/A5
images, `AscendDeviceType` mismatches, `socversion` / `bin package` stamps,
`EZ3002`/`TransData` and other per-op-store refusals, and the 310P quant/VL/OCR shapes.
The mechanism, pinned lines and recheck conditions live in `../../soc-platform-paths/`,
which every row links. Inherit `index.md` and the `SKILL.md` rules: match the **left**
cell, read the **middle** cell before following the link, and re-grep a `path:line` at
the pin.

These rows moved here verbatim when `startup-and-load.md` reached the per-file cap; the
grep in `index.md` (`rg -n '<token>' references/first-checks/signature-routes/`) still
finds them, and a startup paste whose *shape* is a SoC/device-type/kernel-package gate
belongs on this page even though its log is a startup log.
